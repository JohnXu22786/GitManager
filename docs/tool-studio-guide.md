# 我的工具：本地订单工具指南

“我的工具”可以在没有 Git 仓库、Harness、账号或 API 密钥的情况下使用。
它提供有限的记录表单、制作计时、交付目标和提醒规则，不是任意自然语言生成软件的服务。

## 开始使用

1. 启动 Git Manager，进入“我的工具”。顶部的 Tasks 和文件夹按钮仍可进入原来的开发工作流。
2. 可以先选择“体验虚构示例”。它在独立的临时项目中实际运行，日期固定为 2026-10-05；
   退出后删除这个一次性例子。不要把真实资料录入示例。它不会被复制到正式工具。
3. 选择“创建我的工具”，填写名称和一个新的绝对路径，例如你的文档目录下的 `MyOrders`。
   父目录必须已存在；项目目录由应用创建。不要选择 Git 仓库、系统临时目录或符号链接。
   没有默认的临时保存退路，也不会覆盖已有目录。
4. 在“字段与阶段名称”中可修改显示名称、添加可选的文字、日期、整数、是/否或枚举字段。
   枚举选项每行一项，不能为空或重复，最多 128 项；先“添加可选字段”，再创建或保存工具。
   已有字段的身份、类型、必填性及阶段结构不能被直接更改。
5. 创建后选择“新增记录”，填写标题和工作内容，其余字段按需填写。日期格式为 `2026-10-06`。
   点击“保存记录”，确认保存完成后才会成为正式记录。

保存位置始终显示在界面上。关闭工具或退出应用不会删除正式项目；再次启动后使用“打开已有工具”
并填写原目录。首版不维护额外的最近工具列表。请自行保管目录位置，并定期复制整个项目目录备份。

## 日常记录与日期

列表支持查找、未完成、等待和临期筛选。详情可编辑业务信息、改变状态、查看原始事件和派生结果。
完成或取消后历史仍保留。状态变化记录实际带时区的时间戳，非法转移和未来发生的事实会被拒绝。

- 项目创建时固定当前系统的 UTC 偏移，之后按该项目日历计算整日，不自动切换夏令时
- 使用日历日，不推断工作日、节假日或营业时间
- 没有开始制作日期时，制作时间显示“无法确定”
- 原始承诺日期是事实；规则可以改变显示目标，不能改写原始承诺
- 显示目标延后不代表已经通知客户或取得客户同意
- “填写此项”未勾选表示缺失，与已填写的空字符串、0 或“否”不同

### 设置的版本边界

每笔记录保留创建时的字段规范版本。新增可选字段后，旧记录仍可查看和编辑原有字段；
新增字段仅适用于使用新版本创建的记录。旧记录表单会说明这一边界，不会显示无法保存的新字段。
应用不会替旧记录填入默认值，也不会自动迁移或重写原始事实。修改显示名称不会改变字段身份。

## 修改规则前先看结果

1. 从一笔记录点击“按我的做法修改”
2. 填写修改原话和理由，选择适用范围；勾选“也修改所选范围的制作计时”或“跟进提醒”时，
   相应做法才会应用到该范围。未勾选的保留各笔记录与未来默认各自的规则。点击一个计时/提醒选项会自动勾选它
3. 点击“在副本上演练两种结果”，查看实际执行结果和已有决定的检查结果
4. A 保留原承诺交付日期；B 按暂停天数顺延显示目标，两者保留原始承诺
5. 核对后选择“采用这个结果”。只有存储确认后才会生效

你可以修改副本的承诺日期、允许的状态转移或演练日期。正式记录不会随之改变。
将时钟推进到未来的演练仅供比较；采用前要回到当前日期重新演练，避免把未来事件保存成事实。
早于既有事实的演练日期会被拒绝。保存原话不等于应用已经理解或实现不受支持的要求。

四种范围：

- **只改这一笔**：不改变未来新记录的默认规则
- **只用于以后新建的记录**：已有记录保持原规则
- **当前未完成和以后新建的记录**：确认时冻结未完成记录集合，排除完成或取消记录
- **全部历史和以后新建的记录**：改变派生结果，保留原始内容、承诺、完成和状态事件

切换范围保留你的勾选。把某一笔已经采用的计时或提醒扩展到未来记录时，也要明确勾选该做法；
不会只因表单显示了那一笔的值就扩散到其他记录。改变勾选后须重新演练。

范围和项目版本一并冻结。期间另一窗口增加、编辑或完成记录，必须重新读取并演练。
“两种都需要”“都不合适”“不知道或以后再决定”只保存待解决决定，不激活任何规则。
首版不自动从自由文本推导条件分支；需要的分支无法明确表达时仍保持待解决。

## 确认过的意图与安全撤回

有效决定会成为下一次规则修改的检查项。冲突会指出原决定和不一致的实际结果。
如果确实改变主意，展开“明确替代以前的决定”，选择旧决定，重新演练后确认；
未选中的有效决定仍会接受检查。解决暂缓事项也通过新的明确替代决定完成。

在“决定历史”选择“预览撤回这次规则改变”，检查保留记录、事件、后续独立规则和冲突，
再确认撤回。撤回在当前数据上产生补偿规则，不恢复整库旧快照。
后来的新记录、备注修改、完成事实和独立规则不会被删除。仍有后续依赖冲突时，自动撤回被阻止。
一个被更窄决定替代的旧决定可能仍作用于其他记录，因此仍可以请求真实撤回预览。

## 可选的结构化提案交换

展开“导出需求 / 导入结构化提案”。没有 Harness 时，以上内置流程仍完整可用。

1. 填写脱敏后的请求，以及每项有效决定的已核对摘要；选择本地规则作用对象及范围
2. 可选关联一个已存在的开发任务。不关联任务也可使用全部本地功能
3. 生成需求包，检查展示的完整 JSON。应用生成新的虚构记录，不自动导出真实字段值或历史。
   规范显示名称、你填写的请求和意图摘要也可能含私密信息，请核对
4. 勾选确认，填写新文件的绝对路径并保存。应用不会覆盖已有文件或自动发送给外部服务
5. 你可以将这个文件自行交给已有的 Harness。文件里的 `proposal_template` 是完整的严格提案模板
6. 将提案保存为本地 JSON 文件，填写路径并导入。结构检查通过只代表数据形状可接受
7. 选择候选、范围及需要明确替代的旧决定，执行本地演练，分别检查真实记录的前后影响、未来默认和虚构副本结果，核对后采用或保存待解决结果

导入的 `passed` 声明不是执行证据。提案不能包含脚本、命令、任意文件路径、依赖或未知操作。
最多 1 MiB、64 层 JSON 容器，另有候选、记录、步骤和节点数量限制；失败不会改变正式项目。
导出前选择的示例目标应与之后的范围一致，不一致的包会被拒绝，需要重新生成匹配的提案。

**关闭、切换工具或重启应用后，必须重新导出当前需求包。** 首版仅在本次打开期间保留用于校验导入的
不可变导出上下文。不能直接恢复一个旧导出上下文，也不会接受来历不明的孤立包。项目或提案时钟变化后
也可能需要重新导出。导出文件含模板，但导入时只应提供完整的 `proposal_template` 对象。

任务关联读取当前源码指纹，不使用旧审查标签替代。采用后保存有限的来源身份和证据绑定信息，
不改写开发任务、既有审查结果或任务存储格式。重新打开时会检查保存的关联。
缺失、移动或改变的任务使来源关联失效，但不删除已保存规则，也不阻断日常记录和无关联的本地修改。
“本地已执行”“任务来源仍匹配”“外部作者真实性”是不同的问题；本应用不认证外部作者身份。

## 保存失败、并发和恢复

- **未保存 / 正在保存**：输入仍在当前界面中，尚不能当成落盘成功
- **已保存**：项目存储已确认提交
- **证据过期**：重新读取当前内容并演练，不能使用旧的成功结果
- **保存失败且结果未知**：点击“重试同一次操作”。应用保留原候选、操作身份和时钟，避免重复产生业务效果
- **结束重试并重新读取已保存项目**：明确放弃这次重试，读取当前磁盘状态。上次操作可能已经提交，
  这不是取消或撤销，请核对记录和决定历史。关联任务消失时也可这样恢复独立的本地工作
- **创建失败且无法改位置**：点击“结束创建重试并核对原目录（保留输入）”。应用只读取核对原位置；
  找到同次创建的已保存项目就打开它，否则保留原文件和表单输入，让你重新选择位置。
  若原目录无法读取，结果仍属未知，之后需核对；结束重试不代表撤销已保存的项目
- **另一窗口已经保存**：保留输入，读取新版本；旧草稿需明确放弃并重新读取，不能静默覆盖
- **只读诊断 / 不支持的格式**：保留原始字节，停止写入。不要手工把损坏指针改成空项目；先复制整个目录

文件使用独立版本化快照、项目锁、校验和及当前指针提交，不自动清理历史。
读不出或版本较新的数据不会被“空白成功”覆盖。保留输入仅限当前应用进程，未提交草稿不会跨进程保存。
磁盘、权限、锁或项目移动错误都可能阻止保存。需要完整恢复时使用经过核对的项目副本，
不要把整库恢复和业务规则撤回混为一谈。文件未加密。

## 开发模式与能力边界

顶部 Tasks、仓库文件夹按钮和原有状态、分支、worktree、日志、审查及验证流程继续可用。
我的工具不会迁移或重写 `tasks.json`、`recent_repos.json` 或仓库数据。主动打开一个仓库仍按原功能更新最近仓库记录。
业务数据不会由此功能自动上传；应用原有更新检查、Git 远端及显式开发操作仍可能联网。

构建与运行：安装项目要求的 Rust 工具链和平台库后，在源目录执行 `cargo run --locked`。
验证使用 `cargo test --all-targets`；构建使用 `cargo build --locked`。
代码或 CI 通过不等于已经发布发行版。系统字体和输入法由平台提供；自动化 Unicode 输入测试不能代替
真实系统中文输入法的组合输入、候选选择及物理设备测试。
