# Common factual admission (ephemeral proof only)

`ProductStore::verify_owned_preview` accepts exact captured sources, a complete
source-span request, and an opaque `AcceptedPreviewLifecycle`. It independently
rederives the inventory, whole-pair typed rules, lifecycle witnesses, retained-data
invariants and historical capture recipe. Serializable reports and requests are
untrusted diagnostics/suggestions; neither can construct the proof or acceptance.
`revalidate_owned_preview` repeats the proof against the current complete snapshot,
including the active decision graph, authored bytes and producer provenance.

The production `LifecycleAcceptanceHost` prepares a source/frame-bound disclosure
with concrete `LocalRuntime` supporting observations. Its `show` method displays
the interpretation, purpose, scope, exact predicates, sources and witnesses; only
its explicit acceptance button consumes the challenge and mints acceptance.
The separate fixture entry point is `cfg(test)` and marks its event synthetic.
There is no production Boolean, JSON receipt or synthetic-operator switch.
The host component is available to the next preview controller; this milestone
does not install a runnable preview or a durable adoption route in the studio.

## Closed initial grammar

All actions must be explicitly covered. Every changed column or observable must
have an exact supported projection recipe, even when policy-free. UI enablement
for common factual actions obeys the same independence rule as action guards.
Existing scalar-scoped lineages, active retained decisions requiring outcome comparison, owner/reference mutations,
archives, changed constraints, callbacks, selections, partial arithmetic/date
expressions, policy-derived action arguments and unsupported identity consumers
are refused at a concrete site. Policy dependencies close monotonically across
all writers in both complete sources; exact accepted lifecycle equality sites
receive a separate facet, never a global removal of field taint.

Supported common facts include immutable-owner reference links, global
text-keyed registries, directly addressed receipt updates, owner-local
auxiliary rows with exact dedup gates, and terminal append history. An auxiliary
absence gate contains only its single verified Create: nested or intervening
producers cannot invalidate the absence observation before that write. The history
rule verifies all retained sequence values are distinct 1 through count and all
producers use the same untruncated count-plus-one rule. No source may archive,
reassign or otherwise mutate history. Its only observation is inert stored fields
in sequence order. This closes ID tie-breaking, but does not claim raw IDs match.

Root writers need original unfinished admission even for equal-value updates.
Policy-controlled root writes also prove active-target provenance; an archived
unfinished row cannot turn a private branch into a deterministic transaction
failure. Retained active revisions reserve headroom for the runtime contract's
maximum cumulative fuel, excluding policy-selected revision overflow.
Mixed spans preserve lifecycle; completion is an isolated guarded transition.
A preserved lifecycle read must resolve to the exact root record type and owner
identity; a same-named field on an owned auxiliary is not a lifecycle witness.
Every paired variant authenticates its declared root against derived binding and
immutable-owner identities, then checks every target against that same frontier.
Unbound paired replacements and multi-root spans are refused. A one-sided
insertion may establish an exact active-root traversal and gate its owned body.
Common shared writes cannot depend on private policy, owner traversal cannot
silently become a cross-root frontier, and potential policy-dependent deterministic
failures are not resource exceptions. Ordinary interpreter fuel/collection limits
remain unchanged. A separate cumulative proof budget reserves full interpreter
fuel for each replay/projection and bounds all analysis passes and captures.
Child elapsed limits inherit the remaining host deadline; cancellation is checked
before loading the store. Text lowercase is admitted only for literal inputs whose
actual Unicode expansion fits the runtime byte bound.

## Historical recipe and explicit limits

Root view membership and ordering also require a proof: untruncated queries use
stable own-row fields for ordering and for historical membership. A predicate may
instead exclude completed roots with a leading exact accepted facet, provided the
query also excludes archived roots. Shared-fact-dependent historical selectors or
sort keys are refused even when identical in both authored sources; capturing
columns does not freeze row membership. These rules preserve authored selectors.

Every root view column, including unchanged transitive list displays, has an exact
source-qualified recipe. Existing completed/archived roots capture the baseline
value in a private map with mandatory key presence. Candidate-only Boolean columns
have a host `Optional<Boolean>` type and explicitly captured Null absence; an
absent storage key is never treated as Null. Candidate-only root counts instead
have Boolean per-root contributions and an explicit false baseline contribution,
with their new aggregate meaning disclosed. Root count headers remain exact and
untruncated. Time/session-dependent historical columns are refused; a temporal
root count requires a leading accepted completed-false short-circuit.

Reports explicitly mark raw observation comparison unsupported when fresh IDs
can shift, nullable column schema differs, or a new count lacks a baseline.
No expected observation is rewritten and no active retained obligation is silently
passed. The proof contains no executable lowered program, continuation, adoption
conversion or persistent metadata. Deterministic lowering, runtime sealing and
protected interactive execution belong to the subsequent execution milestone.
